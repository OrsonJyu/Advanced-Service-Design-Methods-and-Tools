# 版本、历史与同步

## 版本号
当前 `VERSION` 是 **0.1.0**。它表示资料库状态，不是课程评分、酒店上线版本或 Figma 官方版本。

采用 `MAJOR.MINOR.PATCH`：
- MAJOR：项目结构或对外解释有不兼容调整。
- MINOR：新研究阶段、主要成果或一次有意义的归档补齐。
- PATCH：勘误、链接、元数据和不改变结论的修订。

普通工作提交不必每次升级版本。有意义的版本更新必须同步修改 `VERSION`、`CHANGELOG.md` 和 `PROJECT_STATUS.md`。

## 三层历史
1. Git commit：保存每次可审查的文件变更。
2. CHANGELOG：面向读者解释每个版本的重要变化。
3. 来源、日期与 SHA-256：定位导入文件并核对字节；认证信息遮盖需写明转换。

首次归档使用注释标签 `v0.1.0` 固定快照。标签只标记已存在的提交；不覆盖已发布标签。

## 同步流程
开始前检查工作区、分支、远端及未推送提交，然后 fetch。干净且可快进时同步；有分叉时保留双方内容并解决可判断的冲突。不要 force push。

完成后更新状态、版本记录与成果登记，运行验证、检查差异，只提交本任务内容。推送前再 fetch，检查并发变化；正常 push 后核对远端 SHA。分支保护要求 PR 时，使用工作分支并创建 PR，保持未合并状态。

## 设计文件
Figma 可编辑原稿与 GitHub 是两种资料载体。每次重要设计变更应新增有日期的文字和视觉快照，并更新成果登记表。在线链接、文字导出、PNG、PDF 与原生设计文件要分别记录，避免将链接视作备份。
